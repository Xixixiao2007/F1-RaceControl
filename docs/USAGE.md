# HA-F1-RaceControl —— 使用说明

**交付物**：`HA-F1-RaceControl-v3.2.0.apk`（92.7 KB，versionCode 22 / versionName 3.2.0，
minSdk 23 / targetSdk 23，Android 6.0 及以上）

桌面上显示的名字是 **F1 Race Control**。

> 与上一代 `HA Viewer`（`com.haf1.entitylist`）**包名不同**，
> 两个 App 可以同时装在一台手机上，互不覆盖。

---

## 一、装之前要有什么

**什么都不用准备。**

不需要 Home Assistant、不需要装 `f1_sensor` 集成、不需要账号、不需要令牌。
App 直接连 F1 官方的公开计时服务，打开就能用。

> **没比赛的时候消息列表是空的** —— 这是正常的，官方只在该场次有数据时才推内容。
> 不过**赛刚结束之后它还会留着那一场的数据**（实测赛后一小时仍能收到整场几百条），
> 所以赛后打开通常还能回看。

顶部状态行会一直说明当前处在哪一步：

```
… 连接中
… 已连上官方流，等数据…
⏱ 实时   <会议> <环节>  N 条  第 x/y 圈
… 连接出错，即将重试  |  <错误原文>
```

**看不到数据时先看这一行**，它会告诉你卡在哪。

---

## 二、装 App

1. 从 [Releases](../../releases) 下载 `HA-F1-RaceControl-v3.0.1.apk`
2. 拷到手机（数据线 / 网盘 / `adb install` 都行）
3. 手机上打开这个文件，系统会问「是否允许安装未知来源应用」，允许后安装

Android 6.0 上如果提示「解析包时出现问题」，多半是文件传输过程中损坏了 ——
重新拷一次，或者核对 SHA256（见 Release 说明）。

## 三、首次配置

**不需要配置。** 装完打开就能用 —— App 里没有任何连接参数要填。

想调整就点状态行右端的**设置**（在「精简 / 全部」那个切换的右边）：

| 分组 | 有什么 |
| --- | --- |
| **数据源** | 只有说明和一个「测试能否连上官方流」按钮（真的去握手一次）|
| **显示与过滤** | 精简模式隐藏哪几类、按车号筛选、排除关键词 |
| **提醒** | 声音 / 震动 / 静音突破 / 双黄升级阈值 / 冷却时间 |
| **试听** | 不用等比赛，当场听声音和震动 |
| **关于** | 显示当前装的版本号 |

## 四、界面上有什么

### 竖屏：顶部旗语栏 + 消息列表

```
┌────────────────────────────────────────────┐
│ 黄旗  3,7      │ 双黄旗  12                │  ← 多种旗语纵向分隔

│ ⏱ 实时  Bahrain Grand Prix Race  327 条    │  ← 状态行
├────────────────────────────────────────────┤
│ 18:08:52 [黑白旗] 黑白旗警告：比尔曼(87)…  │
│          BLACK AND WHITE FLAG FOR CAR 87   │
│ 18:07:10 [其它]   仲裁：1 号弯 诺里斯(1)…  │
│ …                                          │
└────────────────────────────────────────────┘
```

### 横屏：左右分栏 + 最右一条窄框图标条

```
┌───────────────────────┬─────────────────┬──┐
│ 消息列表              │ 右侧面板        │◎ │ ← 赛道图
│                       │                 │◍ │ ← 轮胎进站
│                       │                 │≡ │ ← 成绩
│                       │                 │☂ │ ← 天气
│                       │                 │⏱ │ ← 最快圈
│                       │                 │ⓘ │ ← 环节
└───────────────────────┴─────────────────┴──┘
```

点最右那条图标就切换右栏内容，当前项高亮。默认停在**赛道图**。

### 顶部旗语栏

多种旗语并存时**纵向分隔**，每段两行：上面旗语名，下面它涉及的区段
（轨道级的写「全场」）。

优先级仍然是 **红旗 > 安全车 > VSC > 双黄旗 > 黄旗 > 绿旗**，
但**不再只显示最高的那一个** —— 同时存在的会全部列出来，各占一段。

> 为什么轨道级和区段级要分开写：实测官方消息里**根本不存在
> `Scope=Track` 的黄旗** —— 全赛道黄旗只出现在 `TrackStatus` 状态流里。
> 所以「全场」那一档不是猜的。

### 状态行

| 显示 | 含义 |
| --- | --- |
| `… 连接中` | 正在和官方服务器握手 |
| `… 已连上官方流，等数据…` | 连上了，服务端此刻还没推内容 |
| `⏱ 实时  <会议> <环节>  N 条  第 x/y 圈` | 正常收到数据 |
| `… 连接出错，即将重试  \|  <错误原文>` | 连不上，App 会自动重试 |

**看不到数据时先看这一行**，它会告诉你是没连上、还是服务端没内容。

### 精简 / 全部

点状态行右边那个词切换。

- **精简**（默认）：隐藏**被套圈的蓝旗**和**删圈速通报**。
  解除信号（`CLEAR` / `TRACK CLEAR`）**不隐藏** ——
  藏掉它黄旗会「莫名其妙就结束」，看不到是哪个区段被解除
- 具体隐藏哪几类，可在「设置 → 显示与过滤」里**逐项勾选**。
  默认策略下的隐藏比例是 253/697 ≈ 36.3%
- **全部**：一条不落

### 右侧那 6 屏

| 图标 | 面板 | 内容 |
| --- | --- | --- |
| ◎ | **赛道图** | 圆环 + 各区段旗语颜色 |
| ◍ | **轮胎进站** | 22 个位置、三列每列 8 行、**顺序按赛道位置** |
| ≡ | 成绩 | 名次 + 差距 / 间隔 + 轮胎 |
| ☂ | 天气 | 气温 / 赛道温 / 湿度 / 风 / 雨 + 全赛道状态 |
| ⏱ | 最快圈 | 个人最快圈排行 |
| ⓘ | 环节 | 会议 / 赛道 / 环节 / 剩余 / 圈数 + 前三名 |

**赛道图为什么是圆环**：真形状要靠 `Position.z`（赛道位置流），那需要 F1TV 订阅，
**实时拿不到**。所以用区段均布的圆环代替。环上的段数取「本场出现过的最大区段号」，
不依赖任何外部数据表 —— 官方没有任何文件写出过区段总数。

## 五、提醒是怎么触发的

### 会响的

下面这几种**除了全屏横幅，还会在通知栏留一条**（锁屏上也可见）。
横幅负责当场叫醒你，通知栏那条负责事后还能查到 —— 你要是正好没看手机，
回头下拉一下就知道刚才响的是什么旗语。

| 事件 | 响应 |
| --- | --- |
| **红旗** | 全屏红 + 循环警报音 + 三长震 + 点亮屏幕 + 通知栏 |
| **安全车部署** | 全屏橙 + 循环音 + 两震 + 点亮屏幕 + 通知栏 |
| **VSC 部署** | 全屏黄 + 循环音 + 一长震 + 通知栏 |
| **双黄旗持续 >15 秒** | 全屏黄 + 音 + 三短震 + 通知栏 |
| **双黄旗刚出现** | 一声短音 + 一短震（不弹全屏） |
| **黄旗 / 黑白旗** | 一声短音 + 一短震 |
| **安全车结束 / VSC 结束** | 一声短音 + 一短震（不再吓一次） |

**超强提醒默认突破静音模式**（走闹钟通道）。现场看比赛时手机多半是静音，
不突破就可能漏掉红旗。可以在设置里关掉。

### 不会响的

- CLEAR 解除
- 蓝旗
- 圈速因超赛道限制被删
- 绿灯、格子旗（只闪动 + 配色）

> **仲裁「复核完毕，不予追究」也不会响，但它不会被隐藏。**
> 它看起来像"查完没事"，其实是一次事故的**结论** ——
> 你要能知道「刚才那个事故，赛会看过了，不罚」。所以它在列表里看得见，
> 只是不吵你。

### 关于双黄旗的特别说明

**双黄旗不会立刻弹全屏。** 它先给一次轻提醒，然后等 15 秒：

- 15 秒内收到该区段的 `CLEAR` → 判定为**系统测试**，不升级
- 15 秒后仍未清除 → 升级为全屏超强提醒

为什么这么做：实测一个比赛周末有 **142 条**双黄消息，但只对应 **24 个真实事件**。
如果把每条都当超强提醒，你一个周末会被自己的手机吓 **146 次**。

而且双黄旗的存活时长分布是双峰的，最短只有 **1 秒** ——
3 秒的双黄不可能是真事故，那就是赛道系统的测试或抖动。

因为闪动是即时的，**你不会损失任何信息**，只是不会被吵。

可以在设置里改成：

- 只闪动，不提醒
- 只轻提醒，不升级
- 轻提醒 + 仅**大面积**（同时 ≥3 个区段）才升级（最安静，**实测约 10 次/周末**）

默认这一档（轻提醒 + 持续超时升级）**实测约 23 次/周末**：
3 次红旗 + 1 次 VSC + 19 次双黄事故。这个数是用真实客户端代码在
697 条真实比赛数据上跑出来的，不是估算。

## 六、设置项

### 回放测试（假数据）

**不比赛的时候也能把界面完整跑一遍**，这是它唯一的用途。

用官方归档里的**一整场真实比赛**来当数据源：文件里是一条完整时间线
（先一份完整快照，之后逐条放增量），下发格式和线上 WebSocket 逐字节同构，
所以解析和渲染走的是和实时**完全同一份代码**。

| 项 | 说明 |
| --- | --- |
| 选择 .rclog 文件… | 打开系统的文件选择器挑一个回放文件。**不需要任何存储权限** |
| 关闭回放（改回官方流）| 一键回到实时数据源 |
| 回放倍速 | 10 / 30 / 60 / 120 / 300 倍。整场 4 小时，60 倍就是 4 分钟 |

**示例文件不在 APK 里**（v3.2.0 起）：到 [Releases](../../releases) 下载
`.rclog`，用上面那个按钮选它就行。文件放哪儿都行 —— 下载目录、网盘、U 盘
都能选到，因为用的是系统文件选择器。

两个示例文件的区别在**接上时那一刻**：

- **`…_race.rclog`（从头看）** —— 快照点在第 12 分钟，接上时只有 1 条消息，
  之后旗语栏逐步长出来。
- **`…_race_mid.rclog`（中途接入）** —— 快照点在第 2 小时 40 分，一接上就是
  **完整体**（194 条历史消息 + 22 辆车全字段）。这模拟的是「比赛过半时打开
  App」，也正是真机上闪退的那种负载。

选完文件后，下面那行小字会显示文件**自带的元信息**（哪场比赛、多长、
接上时有多少条历史消息）。没有元信息头的文件照样能放，只是显示不出这些。

放出来的消息时间会被改成「现在」，所以**提醒、闪动、全屏横幅都会真的触发**；
快照里的历史消息仍然是旧的，不会被当成新消息炸你一屏。

回放**只放一遍就停**，不循环、不连网络。想回到正常使用，点
「关闭回放（改回官方流）」再保存即可（主界面会自动重启数据源，不用杀进程）。

### 数据源

只有一个说明和一个按钮：**「测试能否连上官方流」**。点它会真的去和
`livetiming.formula1.com` 握一次手，告诉你通不通。**没有任何要填的字段。**

（上面那个「回放测试」也在这块，正常使用时选「官方流」就行。）

### 显示与过滤

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 新消息闪动 | 开 | |
| 看消息时不熄屏 | 关 | 主列表一直亮着。**不需要权限**；费电，看比赛时再开。和「提醒」里的「超强提醒时点亮屏幕」是两条 |
| 默认隐藏噪音（精简）| 开 | 总开关，见上 |
| └ 隐藏蓝旗 | 开 | 被套圈的蓝旗，量最大（正赛里占 42.9%）|
| └ 隐藏解除信号 | **关** | 藏掉它黄旗会「莫名其妙结束」，所以默认不藏 |
| └ 隐藏删圈速通报 | 开 | 以 `CAR ` 开头且含 `DELETED` 的那种 |
| 只看某辆车（车号） | 空 | 填 `44` 就只看 Hamilton 相关 |
| 排除关键词 | 空 | 每行一个，对消息全文做子串匹配 |

### 提醒

| --- | --- | --- |
| 声音 | 开 | |
| 震动 | 开 | |
| 超强提醒时点亮屏幕 | 开 | |
| 超强提醒突破静音模式 | **开** | 走闹钟通道 |
| 黄旗 / 黑白旗给轻提醒 | 开 | |
| 超强提醒自动停止 | 15 秒 | 0 = 必须手动点「知道了」 |
| 同类型提醒冷却 | 60 秒 | 红旗不受此限制 |
| 双黄旗策略 | 轻提醒 + 持续超时升级 | 见上 |

### 试听（就在设置页最下面）

改完上面的开关，**不用连 HA 也不用等比赛**，直接点这三个按钮就能验证：

| 按钮 | 会做什么 |
| --- | --- |
| 试听：轻提醒 | 一声短音 + 一短震（黄旗那种） |
| 试听：超强提醒 | 重复警报音 + 循环震动，响 4 秒（红旗那种） |
| 试听：全屏横幅 | 弹出超强提醒的全屏样子 |

**注意「超强提醒」走的是闹钟音量，不是通知音量。** 点了没声音，先把手机
侧键按一下看看是不是在调媒体音量，再去「设置 → 声音」把闹钟音量调起来。

## 七、遇到问题

**状态行一直显示「连接中」或「连接出错，即将重试」**

看它后面附的**错误原文**：

| 错误 | 意思 |
| --- | --- |
| `UnknownHostException` / `failed to connect` | 手机到 `livetiming.formula1.com` 不通。换个网络（移动数据 ↔ Wi-Fi）再试 |
| `negotiate HTTP 4xx/5xx` | 没拿到连接令牌。App 会自动重试，通常几秒内自愈 |
| `WebSocket 握手失败：HTTP 4xx` | 令牌被服务端拒了（令牌是一次性的，被复用就会这样）。会自动重新申请 |
| `空闲超时（已发心跳但无响应）` | 连上了但服务端一直没发数据，App 会重连 |

**列表一直空着，但状态行显示「已连上官方流，等数据…」**

连接是好的，只是服务端此刻没有内容。官方只在该场次有数据时才推消息，
两场比赛之间可能确实是空的。**赛刚结束之后通常还留着那一场**，可以回看。

**列表有条数但一条都看不见**

v3.0.1 修掉了这个（v3.0.0 是白字白底的显示错误 —— 文字是白的、行底色也是浅的）。
去「设置 → 关于」确认版本号是 **16 / 3.0.1**。

**警报音不响**
检查手机是不是把**闹钟音量**调成 0 了（超强提醒走的是闹钟通道，不是通知通道）。
或者去设置里关掉「突破静音模式」。

**超强提醒没有弹出全屏**
Android 6.0 上如果开启了「悬浮窗」类的系统限制，或者有省电优化策略，
后台弹窗可能被拦。把本 App 加入电池优化白名单。

**中文显示成方块**
Android 6.0 自带中文字体，正常不会。如果刷了精简 ROM 缺字体，只能换 ROM。

## 八、怎么在不比赛的时候测试

### 手机上：直接放回放（最省事，也最接近真机）

先到 [Releases](../../releases) 下载一个 `.rclog` 示例文件（比如
`…_race_mid.rclog`），然后：设置页 ->「回放测试（假数据）」->
「选择 .rclog 文件…」-> 选它 -> 倍速 60 -> 保存。

**不用网络、不用电脑、不用等比赛**（文件下好之后连网都不用）。
文件里是 2026 巴林站正赛（10 月 4 日那场）的真实数据，含两轮安全车、
多次双黄旗、22 辆车、327 条赛事控制消息。

因为它走的是和实时完全同一份解析和渲染代码，所以「会不会崩」
「面板画得对不对」「提醒响不响」都能在没有比赛的时候验出来。

### 造新的 .rclog（换一场比赛）

```bash
# 先看这一年都有哪些场次（探路脚本在 dsh/tools/probe_archive.py）
python dsh/tools/probe_archive.py

# 造文件：--snapshot-ms 决定"模拟什么时候打开 App"
python tools/build_replay_pack.py \
    --session "2026/2026-09-26_Azerbaijan_Grand_Prix/2026-09-26_Race/" \
    --id baku2026_race --name "2026 阿塞拜疆站 正赛" --date 2026-09-26 \
    --snapshot-ms 740000
```

产物只有一个文件：`tools/mock_data/baku2026_race.rclog`。
它**一份两用** —— 桌面单测拿它当夹具，你也可以把它挂到 Release 上
当示例数据给用户下载：

```bash
python tools/release.py --publish --notes <说明.md> \
    --asset tools/mock_data/baku2026_race.rclog
```

> ★ F1 的归档服务器**必须直连**：本机如果开着代理，请求会被 CDN 403 掉。
> 脚本里已经强制绕开环境变量里的 `HTTP(S)_PROXY`。

### 桌面端：跑一遍完整数据管线（不用手机）

```bash
# 用官方归档的真实快照跑完整管线：解析 -> 过滤 -> 分类 -> 翻译
python dsh/tools/f1_pipeline_check.py

# 真连一次官方流，各跑 30 秒
python dsh/tools/f1_pipeline_check.py --live 30
python dsh/tools/f1_java_smoke.py 30
```

这两个跑的是 **App 里的真实代码**（`F1Client` / `F1Feed` / `Translator`），
不是复现，所以能验证协议实现对不对 —— 分片重组、一次性令牌、增量合并这些
只有在真服务器上才测得出来。

### 仓库自带的 mock 服务器

`tools/mock_ha.py` 是本地假 HA（REST + WebSocket）。它现在**只服务于测试套件
和旧的 HA 版界面** —— A 方案不连 HA，所以拿它测不了 A 方案的数据链。

```bash
python tools/mock_ha.py --scenario red_flag --loop
```

它的价值在于：**告警逻辑**（聚类、升级、冷却、振动节奏）与数据来源无关，
用剧本能反复验证。全套测试也是靠它跑的：

```bash
python tools/run_all_tests.py
```

其中单元测试会用**真的回放文件**跑完整管线
（`tools/mock_data/bahrain2026_race_mid.rclog`，也就是挂到 Release 上的那个

## 十、隐私

- 本应用**不收集任何数据**，没有分析、没有崩溃上报、没有第三方 SDK
- 所有通信只发生在**你的手机与 F1 官方服务器**（`livetiming.formula1.com`）之间
- **不保存任何凭据**：连接用的是一个一次性令牌，拿完就开 WebSocket，用完即弃
- 权限只有两个：`INTERNET`（连官方流）和 `VIBRATE`（震动）
